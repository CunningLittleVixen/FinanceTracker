## Возможности

- Регистрация и вход по логину и паролю, несколько пользователей; у каждого свой кошелёк.
- Доходы и расходы с категориями, описанием и датой.
- Бюджеты по категориям с остатком в отчётах.
- Статистика и история с выбором категорий и периода, вывод в таблицах, сохранение отчёта в файл.
- Оповещения: превышение бюджета, 80% лимита, расходы больше доходов, нулевой баланс.
- Переводы между пользователями.
- Редактирование категорий и бюджетов.
- Экспорт и импорт данных в форматах JSON и CSV.
- Автоматическое сохранение данных и загрузка при входе.
- Справка `help` с примерами для каждой команды.

## Быстрый старт

Требуется Java 21. Maven устанавливать не нужно: в проекте есть Maven Wrapper.

```bash
git clone https://github.com/CunningLittleVixen/FinanceTracker.git
cd FinanceTracker
./mvnw test
```

В Windows PowerShell используйте `.\mvnw` вместо `./mvnw`.

### Запуск приложения

Рекомендуемый способ: откройте проект в IntelliJ IDEA, откройте класс `Main` и нажмите *Run*. Консоль IDEA должна работать в UTF-8 (*Settings → Editor → General → Console → Default Encoding*).

Запасной способ из терминала:

```bash
./mvnw -q compile exec:java
```

В некоторых терминалах Windows русский текст при таком запуске отображается неверно, тогда запускайте из IDEA.

Данные сохраняются в папке `data/` рядом с проектом (создаётся автоматически, в Git не попадает).

## Использование

Типичный сценарий (строки после `#` это пояснения, их вводить не нужно):

```text
register                                  # логин и пароль вводятся на следующих шагах
add-category Еда
add-category Зарплата
set-budget Еда 4000
add-income Зарплата 60000
add-expense Еда 300 "обед"
add-expense Еда 500 "продукты" --date 2026-11-10
report                                    # доходы, расходы, остаток бюджета, оповещения
report --categories Еда --from 2026-11-01 --to 2026-11-30
history
export backup.json
exit
```

Если расходы по категории превысят лимит бюджета, отчёт покажет отрицательный остаток и оповещение. В примере из задания (доходы 20 000 + 40 000 + 3 000, расходы 8 300, бюджет «Еда» 4 000, потрачено 800) отчёт показывает общий доход `63,000.00`, общие расходы `8,300.00` и остаток бюджета «Еда» `3,200.00`.

Правила ввода:

- Название категории из нескольких слов берётся в кавычки: `add-category "Коммунальные услуги"`.
- Дата в формате `ГГГГ-ММ-ДД`, будущие даты запрещены. Если дата не указана, берётся сегодняшняя.
- Сумма должна быть положительной, хранится с двумя знаками; в выводе тысячи разделяются запятой (`63,000.00`).

## Команды

Полный список с описаниями и примерами выводит команда `help`. До входа доступны только `help`, `register`, `login` и `exit`.

| Команда | Формат | Что делает |
|---|---|---|
| `register` | `register` | Регистрация нового пользователя и вход |
| `login` / `logout` | `login`, `logout` | Вход и выход (при входе загружается кошелёк) |
| `exit` | `exit` | Сохранение и выход из программы |
| `categories` | `categories` | Список категорий с бюджетами |
| `add-category` | `add-category <название>` | Создать категорию |
| `rename-category` | `rename-category <старое> <новое>` | Переименовать категорию (обновляются операции и бюджет) |
| `remove-category` | `remove-category <название>` | Удалить категорию без операций |
| `set-budget` | `set-budget <категория> <лимит>` | Задать или изменить бюджет |
| `remove-budget` | `remove-budget <категория>` | Удалить бюджет категории |
| `add-income` | `add-income <категория> <сумма> [описание] [--date ГГГГ-ММ-ДД]` | Добавить доход |
| `add-expense` | `add-expense <категория> <сумма> [описание] [--date ГГГГ-ММ-ДД]` | Добавить расход |
| `transfer` | `transfer <логин> <сумма> [описание]` | Перевод другому пользователю |
| `report` | `report [--categories "Еда,Такси"] [--from дата] [--to дата] [--out файл]` | Статистика: доходы, расходы, категории, бюджеты, оповещения |
| `history` | те же опции, что у `report` | Список операций |
| `export` | `export <файл.json или файл.csv>` | Сохранить данные в файл |
| `import` | `import <файл.json или файл.csv>` | Добавить данные из файла |

Пример: `add-expense "Коммунальные услуги" 3000 "за ноябрь" --date 2026-11-10`.

Опция `--out` у `report` и `history` сохраняет вывод в файл; существующий файл не перезаписывается.

## Оповещения

| Оповещение | Когда появляется |
|---|---|
| Бюджет превышен | Расходы по категории больше лимита |
| Использовано 80% и больше | Расходы по категории достигли 80% лимита |
| Расходы превысили доходы | Расходы больше доходов |
| Нулевой баланс | Баланс равен нулю |

После добавления операции показываются оповещения только по её категории, а команда `report` показывает все. Бюджет считается по всей истории операций.

## Экспорт и импорт

Формат определяется по расширению файла. Существующий файл при экспорте не перезаписывается.

| Формат | Содержимое | Для чего |
|---|---|---|
| `.json` | Снимок кошелька: категории, бюджеты, все операции (тот же формат, что у хранилища) | Резервная копия, перенос между пользователями |
| `.csv` | Только операции | Таблицы и обмен данными с другими программами |

CSV: первая строка обязательна, разделитель запятая, кодировка UTF-8:

```csv
date,type,category,amount,description,counterparty
2026-11-10,EXPENSE,Еда,300.00,обед,
2026-11-01,INCOME,Зарплата,60000.00,,
```

- `date` в формате `ГГГГ-ММ-ДД`, `type` это `INCOME` или `EXPENSE`.
- Поля с запятыми, кавычками и переводами строк берутся в кавычки (RFC 4180).
- Файл из Excel в UTF-8 с BOM читается корректно.

Правила импорта:

- Данные добавляются к текущему кошельку, ничего не удаляется.
- Недостающие категории создаются (команда сообщает какие).
- Бюджеты из JSON заменяют бюджеты тех же категорий.
- Импорт выполняется по принципу «всё или ничего»: при ошибке в файле сообщается номер строки, а кошелёк не меняется.
- Повторный импорт того же файла создаст дубликаты операций: одинаковые траты в один день бывают настоящими, поэтому программа их не отбрасывает.
- Переводы из файла попадают в историю как обычные записи и не создают операций у других пользователей.

## Архитектура

Приложение делится на три слоя. Зависимости идут в одну сторону: `cli` → `core` ← `infra`. Ядро ничего не знает ни о файлах, ни о консоли.

| Слой | Пакеты | Ответственность |
|---|---|---|
| Ядро | `core.model`, `core.service`, `core.repository`, `core.exception` | Модель (`Wallet`, `Operation`, `Category`, `Budget`, `Money`, `User`), сервисы (авторизация, операции, категории, бюджеты, статистика, оповещения, переводы, импорт), интерфейсы `UserRepository`, `WalletRepository`, `WalletFormat` |
| Инфраструктура | `infra`, `infra.json`, `infra.csv` | Хеширование паролей (PBKDF2), хранение в JSON, форматы экспорта и импорта (JSON, CSV) |
| CLI | `cli` | Разбор команд, цикл ввода, форматирование таблиц и сумм, сами команды |

Точка сборки приложения: класс `Application` (создаёт хранилища, сервисы и команды и связывает их), точка входа: `Main`.

Ключевые решения:

- Деньги хранятся в `BigDecimal` с двумя знаками и округлением `HALF_EVEN`.
- Операции, категории и бюджеты неизменяемы (`record`), а `Wallet` защищает свои правила сам.
- Баланс вычисляется из операций и не хранится отдельно.
- Названия категорий не зависят от регистра: «Еда» и «еда» одна категория.
- Переименование категории обновляет её операции и бюджет. Удалить категорию с операциями нельзя, чтобы не терять историю.
- Статистика считается по выборке: категории (одна или несколько) и период (границы включительно). Остаток бюджета равен лимиту минус расходы выборки.
- В отличие от примера в задании, «Доходы по категориям» показывает все категории (в том числе «Бонус»), чтобы сумма сходилась с общим доходом.
- Каждая команда это отдельный класс с интерфейсом `Command` (имя, формат, описание, пример), а `help` строится по реестру команд автоматически.
- Ошибки пользователя (`ValidationException`) показываются сообщением и не останавливают программу.
- Пароли хранятся только в виде хеша PBKDF2-HMAC-SHA256 (случайная соль, 600 000 итераций). Хеш содержит свои параметры, поэтому число итераций можно менять без поломки старых записей.
- Логин: 3–20 символов (латинские буквы, цифры, `_`), хранится в нижнем регистре, потому что используется в имени файла кошелька. При неудачном входе всегда одно сообщение, чтобы нельзя было угадать существующие логины.

## Хранение данных

Во время работы данные находятся в памяти, на диск они записываются в формате JSON (Jackson):

| Файл | Содержимое |
|---|---|
| `data/users.json` | Пользователи: логин и хеш пароля |
| `data/wallets/<логин>.json` | Кошелёк: категории, бюджеты, все операции |

- Кошелёк сохраняется после каждой команды, меняющей данные, а также при `logout`, `exit` и при закрытии ввода (например, Ctrl+D).
- Файл записывается через временный файл и затем заменяет прежний, поэтому оборванная запись не портит данные.
- Если файл повреждён или нарушает правила модели, программа сообщает путь к файлу и ничего не перезаписывает.
- Доступ к хранилищу идёт через интерфейсы `UserRepository` и `WalletRepository` из слоя `core`; реализации лежат в `infra`.

## Переводы между пользователями

Команда перевода создаёт расход у отправителя и доход у получателя в категории «Перевод»; в обеих операциях сохраняется логин второй стороны.

- Получатель должен быть зарегистрирован, но не обязан быть в сети: его кошелёк загружается из файла и сразу сохраняется.
- Перевод возможен, только если на балансе отправителя хватает денег. Перевод самому себе запрещён.
- Все проверки выполняются до изменений. Сначала записывается файл получателя, потом изменяется кошелёк отправителя, поэтому при сбое записи деньги не теряются.

## Тесты и качество кода

```bash
./mvnw test      # только тесты
./mvnw verify    # тесты + Checkstyle + проверка покрытия
```

- Тесты: JUnit 5, 390 автоматических тестов: модульные для модели, сервисов, форматов и команд и интеграционные (`ApplicationTest`) с запуском всего приложения на «набранных» командах, включая сценарий из задания, перезапуск программы, переводы между пользователями, экспорт и импорт.
- Покрытие: JaCoCo, около 95% строк. Сборка `verify` падает, если покрытие строк ниже 50%.
- Отчёт о покрытии после `./mvnw verify`: `target/site/jacoco/index.html`.
- Линтер: Checkstyle (правила в `config/checkstyle/checkstyle.xml`), запускается на фазе `verify`; нарушения останавливают сборку.
- Непрерывная интеграция: GitHub Actions (`.github/workflows/ci.yml`) на каждый push в `main` и pull request выполняет `./mvnw verify`, прикладывает отчёт JaCoCo и обновляет бейдж покрытия.

## Ограничения

- Пароль виден при вводе: в консолях IDEA и Git Bash скрытый ввод ненадёжен.
- Нет блокировки после неверных попыток входа.
- Запись нескольких файлов (например, при переводе) не является транзакцией: если после записи кошелька получателя не удастся сохранить файл отправителя, данные временно расходятся.
- Повторный импорт того же файла создаёт дубликаты операций.
- Приложение однопользовательское в каждый момент времени: параллельный запуск двух экземпляров на одной папке `data/` не поддерживается.
