## Архитектура

Приложение делится на три слоя. Зависимости идут в одну сторону: `cli` → `core` ← `infra`.

| Слой | Пакет | Ответственность |
|---|---|---|
| Ядро | `core.model`, `core.service`, `core.exception` | Модель (`Wallet`, `Operation`, `Category`, `Budget`, `Money`) и сервисы (операции, категории, бюджеты, статистика) |
| Инфраструктура | `infra` | Файлы и JSON (в планах) |
| CLI | `cli` | Ввод команд и вывод (в планах) |

Ключевые решения:
- Деньги хранятся в `BigDecimal` с двумя знаками и округлением `HALF_EVEN`.
- Операции, категории и бюджеты неизменяемы (`record`), а `Wallet` защищает свои правила сам.
- Баланс вычисляется из операций и не хранится отдельно.
- Названия категорий не зависят от регистра: «Еда» и «еда» одна категория.
- Переименование категории обновляет её операции и бюджет. Удалить категорию с операциями нельзя, чтобы не терять историю.
- Статистика считается по выборке: категории (одна или несколько) и период (границы включительно). Остаток бюджета равен лимиту минус расходы выборки.
- В отличие от примера в задании, «Доходы по категориям» показывает все категории (в том числе «Бонус»), чтобы сумма сходилась с общим доходом.
