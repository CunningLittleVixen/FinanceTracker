# FinanceTracker

![Coverage](https://img.shields.io/endpoint?url=https%3A%2F%2Fraw.githubusercontent.com%2FCunningLittleVixen%2FFinanceTracker%2Fbadges%2Fcoverage.json)

Консольное приложение для управления личными финансами.

## Запуск

Требуется Java 21.

```bash
./mvnw -q compile exec:java
```

Или запусти `Main` из IntelliJ IDEA. Данные хранятся в папке `data/` рядом с проектом. Терминал должен работать в UTF-8.

Ограничение: пароль виден при вводе.

## Команды

Список всегда доступен по команде `help`. Названия из нескольких слов берутся в кавычки.

| Команда | Что делает |
|---|---|
| `register`, `login`, `logout`, `exit` | Вход и выход |
| `categories`, `add-category`, `rename-category`, `remove-category` | Категории |
| `set-budget`, `remove-budget` | Бюджеты |
| `add-income`, `add-expense`, `transfer` | Операции и переводы |
| `report`, `history` | Статистика и список операций (`--categories`, `--from`, `--to`, `--out`) |

Пример: `add-expense "Коммунальные услуги" 3000 "за ноябрь" --date 2026-11-10`.

## Архитектура

Приложение делится на три слоя. Зависимости идут в одну сторону: `cli` → `core` ← `infra`.

| Слой | Пакет | Ответственность |
|---|---|---|
| Ядро | `core.model`, `core.service`, `core.exception` | Модель (`Wallet`, `Operation`, `Category`, `Budget`, `Money`) и сервисы (операции, категории, бюджеты, статистика) |
| Инфраструктура | `infra` | Файлы и JSON (в планах) |
| CLI | `cli` | Ввод команд и вывод (в планах) |

Ключевые решения:
- Деньги хранятся в `BigDecimal` с двумя знаками и округлением `HALF_EVEN`.
- Операции, категории и бюджеты неизменяемы (`record`), а `Wallet` защищает свои правила сам.
- Баланс вычисляется из операций и не хранится отдельно.
- Названия категорий не зависят от регистра: «Еда» и «еда» одна категория.
- Переименование категории обновляет её операции и бюджет. Удалить категорию с операциями нельзя, чтобы не терять историю.
- Статистика считается по выборке: категории (одна или несколько) и период (границы включительно). Остаток бюджета равен лимиту минус расходы выборки.
- В отличие от примера в задании, «Доходы по категориям» показывает все категории (в том числе «Бонус»), чтобы сумма сходилась с общим доходом.
- Оповещения: бюджет превышен, использовано 80% и больше, расходы превысили доходы, нулевой баланс. Показываются после операции (только по её категории) и в отчёте (все). Бюджет считается по всей истории операций.
- Пароли хранятся только в виде хеша PBKDF2-HMAC-SHA256 (случайная соль, 600 000 итераций). Хеш содержит свои параметры, поэтому число итераций можно менять без поломки старых записей.
- Логин: 3–20 символов (латинские буквы, цифры, `_`), хранится в нижнем регистре, потому что используется в имени файла кошелька. При неудачном входе всегда одно сообщение, чтобы нельзя было угадать существующие логины.
- Ограничения: нет блокировки после неверных попыток, нет транзакционной записи нескольких файлов.

## Хранение данных

Во время работы данные находятся в памяти, на диск они записываются в формате JSON (Jackson 2.22):

| Файл | Содержимое |
|---|---|
| `data/users.json` | Пользователи: логин и хеш пароля |
| `data/wallets/<логин>.json` | Кошелёк: категории, бюджеты, все операции |

- Файл записывается через временный файл и затем заменяет прежний, поэтому оборванная запись не портит данные.
- Если файл повреждён или нарушает правила модели, программа сообщает путь к файлу и ничего не перезаписывает.
- Доступ к хранилищу идёт через интерфейсы `UserRepository` и `WalletRepository` из слоя `core`; реализации лежат в `infra`.
- Ограничение: запись нескольких файлов (например, при переводе) не является транзакцией.

## Переводы между пользователями

Команда перевода создаёт расход у отправителя и доход у получателя в категории «Перевод»; в обеих операциях сохраняется логин второй стороны.

- Получатель должен быть зарегистрирован, но не обязан быть в сети: его кошелёк загружается из файла и сразу сохраняется.
- Перевод возможен, только если на балансе отправителя хватает денег. Перевод самому себе запрещён.
- Все проверки выполняются до изменений. Сначала записывается файл получателя, потом изменяется кошелёк отправителя, поэтому при сбое записи деньги не теряются.
- Ограничение: если после успешной записи получателя не удастся сохранить файл отправителя, данные временно расходятся. Транзакций между файлами нет.
